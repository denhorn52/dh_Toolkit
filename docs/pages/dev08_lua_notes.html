7.08 Lua Notes:

While learning to code in Lua I was somewhat dismayed by the amount of inconsistent, and sometimes contradictory documentation. Two things that had me scratching my head I will address here.

Lua types:

Variables:

Variables are data stored at a memory location. The data type is either a value type or a reference type. The data stored is the value, and the reference is the address. When a value is declared [local A] it is given a name. When a variable is assigned [local A = 2] it is given an address, and the data is stored at that address. The data will have a type. When a variable is read it goes to the memory address to read the data. If a variable is assigned to another variable [local B = A] the result depends on the type of the pre-existing variable A. If A is of a value type, B is assigned a new address and a copy of the data in A is put in the address referenced by B. If A is of a reference type, B is assigned the address of A and references the same data as A.

Value types:

number, string, nil, and boolean are value types.
Assigning a variable with a value type to another variable COPIES the value.

a = 25   -- a holds the value 25
b = a    -- b now has the value 25
a = 32   -- a now holds the value 32  
         -- b still has the value 25

Reference types:

table, function, userdata, and thread are reference types.
Assigning a variable of reference type to another variable COPIES the reference. 

a = {1,2,3,4}  -- 'a' holds the memory address where the value {1,2,3,4} is located. 
b = a          -- 'b' now holds the memory address where {1,2,3,4} is located. 
a = {5,6,7,8}  -- the memory address that 'a' references now holds the value {5,6,7,8}  
               -- the memory address that 'b' references has the value {5,6,7,8}
Ternary operation:

A ternary operator is an expression that returns one result if a condition is true, but a different result if the condition is false. It is a concise form of the logic achieved by using an if-then_else statement. 

if condition then
    return value_if_true
else
    return value_if_false
end

Lua lacks a built-in ternary operator, but it can be mimicked by using the logical and...or operators. This works as a side effect of how Lua evaluates the and...or operators.

Rules:
All three parts of the ternary expression can be a value, a variable, or an expression.
Expression are evaluated from left to right.
'and' operations are evaluated before 'or' operations.
Lua returns the last operand evaluated that results in a true condition.
It's important to remember that in Lua all values except for nil and false are considered to be true. 
 local x = 30
 local A      -- is nil, evaluates to false.
 local A = X          -- Evaluates to true.
 local A = true       -- Evaluates to true.
 local A = false      -- Evaluates to false.
 local A = (x == 30)  -- Evaluates to true.
 local A = (x == 40)  -- Evaluates to false.

Consider first the logical 'and' operator: All operands of an 'and' operation must be true for the result to be true. Stops evaluating when a false operand is encountered then returns false. 

  -- cond is a variable or expression that evaluates to true or false.
  -- exp_B is a value an expression that returns a value.
  
  result = cond and exp_B
  
  If cond is false, evaluation ends, result is false
  If cond is true, evaluates exp_B:
    If exp_B is false returns false
    If exp_B is true returns exp_B
  
  Example:
    
  x = 30
    
  --         false       not evaluated
  result = (x == 40) and "it's true"
  
  cond is false, result is false.
    
  --         true             true
  result = (x == 30) and "condition is true"
  
  cond is true, result is "condition is true"

Consider next the logical 'or' operator: If any operand of an 'or' operation is true the result is true. 

  result = cond or exp_B
  
  If cond is true, evaluation stops, returns true
  If cond is false, evaluates exp_B 
    if exp_B is false returns false
    if exp_B is true returns exp_B

Now combine them: 

 
  result = (cond and exp_B) or exp_C
  
  If (cond and exp_B) is true returns exp_B
    no need to evaluate exp_C
    exp_B was the last operand to make expression true  
  
  If (cond and exp_B) is false, evaluates exp_C
    If exp_C is false returns false
    If exp_C is true returns exp_C
    
  Example:
      
  local x = 30
  
  --          true            true         not evaluated
  result = ((x == 30) and "cond is true") or "cond is false"
  
  result is "cond is true" because it was the last operand 
  evaluated resulting in a true expression.

  --          false           true              evaluated
  result = ((x == 40) and "cond is true") or "cond is false"
  
  The 'and' operation is false so the 'or' operand [exp_C] is evaluated.
  exp_C is a string so it is considered true.
  Therefore the result is the string "cond is false" because it was the 
  last operand evaluated resulting in a true expression.

I think my original confusion was because of the length and complexity some of the "ternary" statements I came across. Sometimes, for clarity's sake, it would be better to use an if-then-else statement.
